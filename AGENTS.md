# AGENTS.md

Monorepo (Yarn workspaces) for a personal blog. Three services plus a shared config package:

- `apps/web` — Next.js 14 frontend, single locale (`cn`). Port 3000.
- `apps/cms` — Payload + Express CMS + Postgres. Port 3001.
- `apps/api` — Hono on Node, public read API. Port 3002.
- `packages/config` — site metadata, single locale strings, biome taxonomy. Source-direct (`workspace:*`).

Frontend never talks to Payload directly; it talks to Hono. Hono reads Payload via Local API for live data, and a JSON snapshot for the globe biome map. AI assist lives entirely inside `apps/cms` (Payload `beforeChange` hooks via Vercel AI SDK). No AI routes in `apps/api`.

## Commands

All commands run from the repo root unless noted. Yarn 3.6.1 with `node-modules` linker, pinned in `.yarn/releases/`. Do not run `npm i` or `pnpm i`.

- `yarn install` — install workspaces.
- `yarn dev` — `docker compose up` (db + cms + api + web). First boot: set `RUN_MIGRATION=true` once to import `data/blog/*.md` into Payload.
- `yarn build` — workspace-scoped `next build` for `apps/web`. `apps/cms` and `apps/api` build inside their Docker images; `yarn workspace cms build` and `yarn workspace api build` exist for local verification.
- `yarn serve` — `yarn workspace web start` against the production build.
- `yarn lint` — `next lint --fix` scoped to `apps/web`.
- `yarn analyze` — bundle analyzer for `apps/web` (sets `ANALYZE=true`).
- No test script. There are no tests; don't search for them.

## Workspaces

Yarn workspaces root. New code goes in one of four places:

- `apps/web/{app,components,layouts,css,src,lib,components/post,components/globe}/...`
- `apps/cms/{src/collections,src/hooks,src/migrations,src/admin,src/lib}/...`
- `apps/api/{src/routes,src/lib}/...`
- `packages/config/src/{site,i18n/cn,biomes}.ts`

## Content authoring

- Blog posts live in Payload (`apps/cms`). The 18 originals were imported from `data/blog/*.md` on first boot and stored as `content.markdown`. New posts use `content.lexical` (Payload's default Lexical editor).
- Authors: `apps/cms` `Author` collection.
- Frontmatter equivalents live in `apps/cms/src/collections/Blog.ts` (`Blog` schema). Schema is a superset of the old contentlayer `Blog` doc: `status` (draft/review/published), `seo` group, `aiSuggestions` cache, per-doc `locale` (default `cn`), `biome` relation.
- `apps/web/components/post/` has two render paths: `LegacyMarkdown.tsx` (sanitized HTML from the `content.markdown` string) and `Lexical.tsx` (Payload Lexical JSON). `app/blog/[...slug]/page.tsx` picks one based on which sub-field is populated.
- Tags are a relational collection (`Tag`). Biome taxonomy is `packages/config/src/biomes.ts` (six biomes; existing 16 tags collapse via an explicit mapping table).
- Drafts are filtered at the Hono layer (`status != 'draft'` in non-dev). No build-time stripping anymore.

## API contract

The frontend calls Hono at `process.env.WEB_API_URL`. Routes:

- `GET /posts`, `GET /posts/:slug`
- `GET /tags`, `GET /tags/:slug`
- `GET /biomes` (JSON snapshot, served from `apps/api/.cache/biomes.json`)
- `GET /feed.xml`, `GET /tags/:slug/feed.xml`, `GET /sitemap.xml`
- `POST /cache/invalidate` (called by Payload `afterChange` hook on `Biome`; regenerates the snapshot)

There is no AI route in Hono. Inline AI assist is Payload-only.

## Path aliases

Configured per workspace. `apps/web/tsconfig.json` carries:

- `@/components`, `@/data`, `@/layouts`, `@/css` → relative to `apps/web/`.
- `@blog/config` → `packages/config/src/index.ts`.
- `@blog/api` → `apps/api/src/index.ts` (type-only re-exports of route shapes).

The legacy `contentlayer/generated` alias is gone. The generic `@/*` no longer maps to `./src/*`; do not reintroduce it.

## Build artifacts

- `.contentlayer/` is gone. If you see `contentlayer/generated` imports, the move to `apps/web` is incomplete.
- `apps/api/.cache/biomes.json` is generated by the snapshot hook; gitignored.
- `public/feed.xml` is generated by Hono at runtime, not by a postbuild script.
- Per-route bundle sizes are reported by `yarn workspace web build`. Homepage globe budget is **< 200 kB gzip** for the dynamic-imported R3F chunk.

## siteMetadata + CSP coupling

`packages/config/src/site.ts` is the single source for site title, locale, theme. CSP lives in `apps/web/next.config.js`. Adding a new analytics or comment provider requires updating the matching `script-src` / `connect-src` / `frame-src` entry there. Giscus `frame-src giscus.app` is the only third-party frame currently allowed.

## Pre-commit

Husky runs `lint-staged` (eslint + prettier) on staged `*.{js,jsx,ts,tsx,json,css,md,mdx}`. Run formatters before committing or the hook will rewrite the staged files.

## First-boot migration

`apps/cms/src/migrations/mdImport.ts` walks `data/blog/*.md` and `data/authors/default.mdx`, POSTs to Payload Local API, writes `data/migration-map.json` (gitignored). Idempotent on source-file mtime + size hash. Gated on `RUN_MIGRATION=true`. Re-run safely; pass `--force` (planned, MVP 2) to bypass the map.
